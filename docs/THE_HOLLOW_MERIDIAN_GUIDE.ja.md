## この出版物について

*The Hollow Meridian* は、コンパクトなゲームデザイン契約であると同時に、マルチエージェント制作プロンプトでもあります。Three.js を用いてデスクトップブラウザ向けに制作する、三人称視点ダークファンタジー・アクション RPG の垂直スライスを1本規定します。画面に表示され、または音として再生されるゲームコンテンツは、リポジトリで管理されたコード、明示的なパラメーター、名前付きシード（seed）から生成しなければなりません。ダウンロード済みの完成モデル、テクスチャ、画像、フォント、アニメーションクリップ、録音済み音声、アセットパックは契約の対象外です。

この出版物は、実装開始前にプロダクトの範囲を固定します。

- 初回プレイ時間は約10～14分
- 安全な拠点（hub）1か所と、5つの主要空間を通る設計済みルート1本
- クエスト1件、空間パズル1つ、敵の基本型（enemy archetype）3種
- 3つの遺物（relic）から選ぶ、意味のある選択1回
- 2段階のボス1体と、2種類のエンディング
- チェックポイント、死亡、復帰、勝利、拠点への帰還を扱うローカルセーブ枠1つ

目的は、狭く限定されたルートの中で深度を生み出すことです。オープンワールドへの拡張、クラフト、ショップ、ランダム戦利品、仲間、マルチプレイヤー、乗り物、キャラクター作成、ボスの追加は、意図的に将来へ先送りされています。

## 世界観とプレイヤー・ファンタジー

舞台は、消滅した都市の真の名前をかつて保存していた廃墟の天文台です。建築は世界設定であると同時にナビゲーションとしても機能します。放射状の梁、同心円環、子午線軌道、文書庫の区画、索引腕、鐘楼骨格、陶器の仮面、灰の流路が、作品固有の視覚文法を形成します。

プレイヤーが操作するのは、骨色の陶器と変色した真鍮を重ねた鎧をまとう、顔のない成人の守護者 **Cartographer** です。Cartographer は分節式の長柄刃と Echo Lantern を携えます。このファンタジーが与えるのは、制約のない力ではありません。空間を読み、タイミングを学び、名前を取り戻し、天文台に保存されたものを束縛するか解放するかを決めるという、統制された方向感覚です。

主要な素材群には、それぞれ明確な役割があります。

| 素材 | 想定される視覚的挙動 |
|---|---|
| Dark basalt（暗色玄武岩） | 広い面に粗い質感と強い質量感を持ち、上向きの面には淡い塵が積もる |
| Tarnished brass（変色した真鍮） | 構造にリズムを与え、局所的な緑青と接触部の磨耗光沢を示す |
| Bone ceramic（骨色の陶器） | 仮面と鎧に用い、シードに基づく亀裂と露出した縁の温かい色を持つ |
| Ember glass（残り火のガラス） | 独立した発光核の周囲に限定された透明表現を持つ |
| Name-light | ダウンロードしたフォントではなく、生成された線状字形と淡いシアンホワイトの誘導表示 |

安定した name-light は淡いシアンホワイトです。不安定な鐘のエネルギーはアンバーホワイトです。深い赤はダメージと重大な警告のためにのみ使います。高彩度の紫を標準の魔法表現にはしません。

## 10ビートで構成されるプレイヤーの旅

形状と素材がプロシージャルに構築される場合でも、ルート自体は設計済みです。

| ビート | 空間と目的 | プレイヤーが得る結果 |
|---:|---|---|
| 1 | **Ash Court への到着** | 移動、カメラ、インタラクション、Mnemonic Keeper、休息用チェックポイントを学ぶ |
| 2 | **クエストの受注** | 2つの方位印（orientation seals）が必要だと知り、ルートを開く |
| 3 | **Orrery Bridge のチュートリアル** | Ashbound Skirmisher と遭遇し、ロックオン、回避、ガード、パリィ、最初の消耗品を学ぶ |
| 4 | **Archive Nave** | 垂直方向の見せ場を読み、Lantern Wraith の圧力に対処し、任意の伝承を発見する |
| 5 | **Meridian alignment** | 決定論的な3環式空間パズルを解き、North Seal を得る |
| 6 | **Bell Foundry** | Bell Sentinel のガードを崩し、Depth Seal を得る |
| 7 | **Shrine での選択** | 戦闘モデルを変える3つの遺物から1つを選ぶ |
| 8 | **Chamber の開放** | 短くスキップ可能な生成演出を起動し、ボスを出現させる |
| 9 | **Unnamed Bell** | 読み取り可能な危険領域と異なる空間ルールを持つ2段階の戦闘を完了する |
| 10 | **束縛か解放か（Bind or release）** | 2つの結末から1つを選び、結果を保存して拠点へ戻る |

プロシージャル・システムは、建築、素材、標識、粒子、制約された変化を構築できます。一方で、劇的なルート、戦闘の順序、視線誘導の優先順位、見せ場のタイミング、各空間の物語上の目的を決めることはできません。

## 瞬間ごとのプレイ

中核となるゲームループは次のとおりです。

1. 建築と光を手掛かりに方向を把握する
2. 戦闘またはインタラクションの状況を読む
3. 移動、防御、攻撃のいずれかに踏み込む
4. スタミナを消費または回復する
5. 効果的なプレイによって Resonance を得る
6. Echo Brand、または遺物によって変更された選択肢を使う
7. 印章を回収し、パズルを解決し、またはクエスト状態を進める
8. チェックポイントに到達し、意味のある状態を保存する
9. 戦闘または物語の条件が変化したルートを再訪する

この仕様は、クリックだけでダメージを与える戦闘、見せかけだけの所持品統計、世界状態を変化させないクエスト、標準の敵を単に大型化したボス、文法を持たないプロシージャルな無作為性を認めません。

## 戦闘モデル

Cartographer が使用できる一連の行動は、限定され、読み取り可能なものです。

- カメラ基準の移動と戦闘時の平行移動
- 弱攻撃の連係
- 溜め強攻撃
- 明確な硬直時間を伴う回避
- ガードと、選択されたパリィ受付時間
- 行動を制約する主要リソースとしてのスタミナ
- パリィ、ダメージ、定義済みの遺物効果から得られる Resonance
- Resonance を消費する対象指定型の行動、Echo Brand

戦闘数値は中央管理された型付きデータに置き、テストの対象にしなければなりません。攻撃判定（hitbox）と被攻撃判定（hurtbox）は、プロシージャル・リグの関節および武器の分節と視覚的に一致し続ける必要があります。入力バッファは許可されますが、成立しないキャンセルは許可されません。カメラ衝突、ロックオン、狭い空間、複数の敵、ボスの画面構成には、それぞれ診断エビデンスが必要です。

### 各敵が教えるルール

各敵は異なるルールを教えます。

- **Ashbound Skirmisher：** 基本的な間合い、読み取り可能な近接タイミング、回避、パリィ
- **Lantern Wraith：** 遠距離からの圧力、溜め動作の認識、横移動、制御された対象選択
- **Bell Sentinel：** ガードへの圧力、強攻撃、体勢耐久（poise）、ボス戦への準備

複数の敵が同時に読み取り不能な圧力を生まないように、戦闘ディレクター（encounter director）が攻撃機会を制御します。

## The Bell Without a Name

![Meridian Chamber 内で第2段階へ移行する The Bell Without a Name](../assets/hollow-meridian-boss-hero.jpg)

*出版物の説明用コンセプトアートです。ゲームプレイのキャプチャや実装済みであることを示す証拠ではありません。*

このボスは大型化した Bell Sentinel ではなく、独立したシステムです。高さ約4.5メートルの構造体は、非対称の環状骨格、吊り下げられた暗色の鐘核、3本の可動式打撃腕、後方へ引きずる索引鎖、段階移行時に割れる無地の陶器製面板を組み合わせています。

第1段階では、読み取り可能な4種類の攻撃を教えます。広範囲の子午線薙ぎ、垂直の鐘打ちとそれに続く拡張する床面環、細い鎖の突き、溜めを伴う共鳴波です。一部の攻撃はパリィでき、規律ある強攻撃またはパリィによって体勢を崩せます。

体力が55パーセントになると攻撃選択が停止し、保護された段階移行が始まります。面板が割れ、鐘核が分離して空中軌道を描き、冷たい name-light が不安定なアンバーホワイトへ変化します。回転する子午線状の危険領域には、視認可能な安全区画が設けられます。第2段階は、プレイヤーが学んだ戦闘ルールを捨てることなく、空間とリズムを変化させます。

ボス契約は、回避不能な確定ダメージ、読み取り不能な攻撃の組み合わせ、隠された危険区画、あらゆる回復機会を排除する最終段階を禁止します。

## RPG の状態、遺物、結果

RPG としての深度は、プレイに影響する少数の状態変化から生まれます。

- クエストの受注によってルートが開く
- 回収した印章ごとに進行状態が変わる
- 3つの遺物から選んだ1つが、実際の戦闘判断を変える
- 消耗品には範囲を限定した役割がある
- チェックポイントと死亡後の復帰が、宣言済みの状態を維持する
- 最後の「束縛か解放か」の選択（bind-or-release decision）によって、視覚的およびテキスト上の結末が変わる
- 拠点へ戻った後も完了状態が保持される

成長要素はレベル上げではなく、意味のある遺物の選択1回です。セーブ・スキーマ（save schema）はバージョン管理され、クエスト状態、印章、選択した遺物、消耗品、チェックポイント識別子、完了状態、エンディングの選択、設定、再割り当てした操作を保存します。チェックポイント設計上必要でない限り、一時的な粒子、敵のアニメーション段階、付随的な戦闘状態は永続化しません。

## ソース生成型のアート、アニメーション、音声

「ダウンロード済みアセットを使用しない」という規則は、最終的に可視または可聴となるメディアに適用されます。監査された開発用依存関係、ブラウザ API、ビルドツール、テストツール、プロファイラーを禁止するものではありません。

プロシージャル生成はコンパイルとして扱われます。生成器には次の要素が必要です。

- 制約された文法とパラメーター範囲
- 名前付きシードと、主張する範囲での決定論的出力
- 重複、ルートの遮断、反復、無効な衝突判定に対する排除テスト
- 詳細度（LOD）、カリング、バッチ処理、プーリング、コストの制御
- 来歴記録と診断表示

キャラクターには、プロシージャル・リグ、型付きキーフレーム、決定論的なポーズ曲線、または生成されたアニメーションクリップを使用します。プロシージャルな動きは、常時揺れ続ける動きで置き換えるのではなく、設計されたポーズと戦闘タイミングを支えなければなりません。

音声は Web Audio の基本要素と空間ノードを使って合成します。目標とする音色には、鐘の倍音成分、制御されたノイズ、エンベロープ、フィルター処理した衝撃音、ルート環境音、戦闘フィードバック、パズル解決音、ボス段階に応じたミックスの変化、明確に異なるエンディング状態が含まれます。重要な音声情報には、視覚的に同等の情報提示が必要です。

## インターフェース、操作、アクセシビリティ

ゲーム契約にはキーボード、マウス、ゲームパッドのサポートが含まれます。会話およびメニューの入力が戦闘行動を起動してはなりません。一時停止中は正準シミュレーションを停止しつつ、非正準のメニュー表示を継続できます。

アクセシビリティの目標には次の項目が含まれます。

- キーボードとゲームパッドの操作再割り当て
- メニューとエンディング効果の動き抑制オプション
- 高コントラストのインタラクション・マーカーとルート・マーカー
- 色だけに依存しない、読み取り可能な予備動作
- 個別の音量スライダー
- 重要な音響合図に対応する視覚的表現
- 精密な戦闘中にカメラ揺れを抑えた、安定したカメラ挙動

これらは仕様上のエンジニアリング要件です。正式な WCAG 適合の証拠ではありません。

## 制作グラフがゲーム契約を使用する仕組み

このプロンプトは、建築、ゲームプレイと戦闘、プロシージャルな世界構築、AI とボスの挙動、RPG と UI のシステム、音声と効果、統合、QA と性能、視覚評価、来歴監査を担当する、範囲を限定した各役割に作業を分配します。

構築担当者（Builder）は自らの成果物を承認しません。決定論的なコードがグラフ遷移を制御します。読み取り専用の評価担当者（critic）が取得済み成果物を評価します。来歴監査担当者（provenance auditor）はリリースを阻止できます。委任される各タスクには、変更を許可するファイル、変更を禁じるファイル、不変条件、合格判定コマンド、必要なエビデンス、予算、再試行上限、ロールバック条件が明記されます。

エビデンスの対象には次の項目が含まれます。

- 固定刻みシミュレーションとリプレイ取得
- 定期および最終状態ハッシュ
- 安定した診断 URL とカメラ状態
- 単一のコミットに紐付いたスクリーンショットとトレース
- 戦闘、パズル、ボス、セーブ、エンディング、アクセシビリティ、来歴のエビデンス
- フレーム時間分布とレンダラー統計
- クリーンなチェックアウトでの再現と、問題のない回帰試験2サイクル

GPU とブラウザをまたぐ視覚出力がビット単位で一致するとは想定しません。制御されたシミュレーション状態には完全一致比較を使用できます。ラスタライズされたエビデンスには、宣言済みの知覚的許容範囲が必要です。

## 出版物の使い方

1. 配置宣言（deployment declaration）、ゲーム契約、体験の柱、反スロップ契約（anti-slop contract）、設計済みルートを読みます。
2. 権限グラフと、委任開始前に存在すべきリポジトリ文書を確認します。
3. システムの章を読み、最低限必要な戦闘、RPG、世界、音声、インターフェース、アクセシビリティの契約を把握します。
4. 専門タスクを割り当てる前にスキーマを採用します。
5. 完全なオーケストレーター・プロンプト（orchestrator prompt）を、リポジトリ内で作業できる有能なコーディング・エージェントに渡します。
6. 専門担当カード（specialist card）をリポジトリのエージェント用ディレクトリに保存します。
7. コンテンツを増やす前に、検証、グラフ状態、エビデンス取得、ロールバックを実装します。
8. 10～14分のルート全体が利用可能なエビデンス予算または計算予算を超える場合は、より小さな実証用スライスから始めます。
9. 1つの識別済みコミットに対してリリース条件を通過するまで、完成を宣言しません。

## 今後、実装が必要なもの

この出版物が説明するのは、目標と制御システムです。現時点のリポジトリには、次のものは含まれていません。

- プレイ可能な Three.js 実装
- 実行可能なタスク、欠陥、グラフ、リリースの各検証器
- 決定論的リプレイと取得基盤
- 生成されたソース・アセットと実行時コード
- 測定済み性能結果
- 受理済みの `run-0001` エビデンス・パッケージ
- 記録済みの修復と検証済みのロールバック
- 宣言済みの判定条件を通過したリリース候補

正確な位置付けは、*The Hollow Meridian* が Evidence Graph の系譜に属する応用 RPG 仕様である、というものです。完成したゲームでも、提案された制作手法がすでに収束したことを示す証明でもありません。
